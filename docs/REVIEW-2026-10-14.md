# Quality and standardization review — 14 October 2026

## Scope and evidence

Reviewed the current source after alpha46 and the subsequent briefing, WIP badge and Windwalk hero-order changes. Re-ran all 36 Lua regression fixtures and release/development Lua assembly validation successfully. These are native mocks and assembly checks, not proof of Warcraft pathfinding, audible sound selection or live native hotkey responsiveness. The latest source changes have not yet been packaged into another alpha.

No gameplay code was changed during this review.

## What is working better

- Shared tutorial runner: narration formatting/rendering, entry generations, fixed-duration camera movement, toolbar creation, click dispatch and cleanup boundaries are centralized. Old callbacks cannot become valid simply because the player revisits the same numbered step.
- Shared training presentation and results: menus, status, pause, completed-state restoration and scoped countdowns have reusable helpers. Activity-specific behavior remains in hooks.
- Cleanup tracks engine-created units and sweeps orphaned summons/transformation products on activity disposal, rather than relying solely on manually created handles.
- Hotkey preparation and input handling retain the audited native command-grid approach. Selection, prerequisites, shop stock, resources, hero learning and target-dependent recognition have focused checks.
- Reflex population rules and stage progression have explicit tests. WIP is presentation metadata and does not disable the activity.
- Windwalk timed creation now puts BM before the SH/TC targets, with tests across all ten timed stages; Hard is tested as BM then TC.
- The new Heroes scene uses shared scopes, scene construction and fixed-duration camera movement. It is a scene prototype, not a completed scripted tutorial.

## Remaining standardization gaps

### 1. Tutorial scene transitions and worker handoffs — highest priority

Camera and Economy still own substantial scene behavior separately. Economy uses stable step IDs and restore records; Camera has a more procedural restoration system. The common runner does not make these scene semantics identical.

Worker placement illustrates the danger of an overly general helper: exact exported building coordinates are desirable, but forcing mobile harvesting units onto coordinates inside trees is not. Camera now bypasses exact-position correction for Peons; Economy also uses native placement for its workers. Make those two explicit shared placement policies: exact structure placement versus native-safe mobile placement.

The latest Economy handoff reissues visible workers and checks idle workers at bounded intervals over five seconds, without ordering hidden miners. It passes orchestration tests but remains an in-game acceptance item. Verify this first. A shared worker handoff should protect construction and player orders, expose its reasons in diagnostics, and avoid accumulating different retry policies in every tutorial.

Introduce a small, explicit step entry/exit/restore convention around attacks, idle-worker tasks and construction. Preserve authored progression and existing stable IDs. Do not rewrite every tutorial or replace actual harvesting with a scripted approximation.

### 2. Completion events versus visibility — medium priority

Result cues currently use a session-level flag and HideResultCard resets it. Current tests check hidden initial render and repeated visible render. This is a fragile boundary: hiding is a presentation operation, whereas starting a new attempt/stage is a gameplay event.

Give each completed attempt a result identity and play its cue once for that identity. Reset on a new attempt/stage, not on arbitrary card visibility changes. Extend coverage to failure/success, Menu/Resume, native menus, save/load presentation rebuilding and the four-Gargoyle celebration.

The sound assignments are centralized, but their event call sites still live across bootstrap, Credits, Hotkey answers and result rendering. Retain one sound configuration and explicit event names; leave naturally occurring Warcraft unit/spell audio alone.

### 3. Shared scoring without cross-exercise ownership — medium priority

Reflex calls JTG.HotkeyAward and JTG.HotkeyScoreStyle. Reuse is good, but a general scoring rule should not be defined in another exercise module. Move only the common award and score styling into infrastructure. Keep clocks, difficulty, completion conditions and high-score keys specific to each exercise.

### 4. Presentation and developer tooling — medium priority

Hotkey and Reflex use shared SetPresentation but still carry individual frame lists, rebuild methods and menu-state restoration. Register their presentation elements declaratively rather than maintaining overlapping hide/show lists. Keep native selection recovery separate; it has engine-specific reasons and should not be casually removed.

Hotkey audit/comparison hooks still appear throughout the runtime activity. Keep diagnostics, but separate the diagnostic mode adapter from normal scored progression where practical. Use the proven native preparation/input mechanics as the stable core, not a new input system.

### 5. Authoring and documentation — lower priority

Editable briefing files are snapshots imported manually into Lua. This has served its purpose, but two editable representations can drift. Choose an authoritative text source per exercise and generate/validate the runtime copy. Initially do this only for Hotkey and Reflex, preserving formatting tags, paragraph breaks and dynamic selection summaries.

The tutorial standard still describes four factories and exact coordinate correction broadly. Update it when introducing explicit mobile placement and the Heroes tutorial. Keep the current reference documents distinct from historical reviews.

## Suggested order

1. In-game confirmation of the Economy Continue handoff and Windwalk hero-key order, then fix any observed failure without changing unrelated behavior.
2. One bounded consolidation pass: explicit scene placement policies, shared worker handoff, and entry/exit/restore for transient tutorial demonstrations. Cover rapid Continue, repeated Back/Topics, Menu/Resume and cleanup.
3. Completion-event audio and shared scoring extraction, with unchanged gameplay and dedicated regression checks.
4. Pack one alpha with a short acceptance checklist, rather than another full hotkey audit. Re-audit only if native input/preparation changes.
5. Continue the Heroes tutorial once the user supplies the script. Use the scene and standardized transitions already available.
6. Keep Reflex marked WIP. Test one smaller, focused reaction loop with users before adding more buffs, modes or scoring complexity. The present implementation has many mechanics, but automated correctness cannot establish that it is enjoyable.

Avoid a wholesale rewrite, a generic framework for hypothetical future tutorials, and a large Combat Micro expansion during this consolidation. Optimize the repeated boundaries that have actually caused regressions.
